# 用户余额查询 API

`GET /api/v1/open/balance` 让客户无需登录面板即可查询账户的钱包余额。该接口使用专门的**用户访问令牌**（`sat-…`）鉴权，与用于推理调用的 `sk-` API Key 是两套不同的凭据。

> **该令牌只能查询余额，不能用于发起推理 / API 请求。** `sat-…` 令牌与 `sk-…` API Key 不可互换：拿 `sat-…` 令牌调用任何网关 / 推理接口都会鉴权失败，反之拿 `sk-…` API Key 调用本接口同样无法通过鉴权。

## 获取访问令牌

- 在账户**个人资料页**自助生成，或由管理员代为签发。
- 格式：`sat-` 后跟 64 位小写十六进制字符。
- 每个账户同一时间**最多一枚**令牌。
- **重新生成**会替换当前令牌，旧令牌立即失效；重新生成需要**账户密码**。
- **撤销**会彻底删除令牌，同样需要账户密码。
- 查看当前令牌不是一次性的——可以在个人资料页反复查看。

## 鉴权方式

以下两种方式二选一：

```text
Authorization: Bearer sat-<64 位十六进制字符>
x-api-key: sat-<64 位十六进制字符>
```

通过查询参数（`?key=`、`?api_key=`、`?access_token=`）传递凭据会被拒绝。

## 请求

```text
GET /api/v1/open/balance
```

无需查询参数或请求体。

## 响应

成功时返回扁平 JSON 结构——**不是**面板 API 使用的 `{code, message, data}` 信封：

```json
{
  "object": "sub2api.balance",
  "schema_version": 1,
  "currency": "USD",
  "balance": 12.3457,
  "frozen_balance": 0.9877,
  "observed_at": "2026-07-31T02:00:00Z"
}
```

| 字段 | 说明 |
|------|------|
| `object` | 固定为 `"sub2api.balance"`。 |
| `schema_version` | 当前为 `1`。仅在字段发生不兼容变更时递增——未知字段应视为向前兼容，如需在破坏性变更影响业务前提前感知，可检查该值。 |
| `currency` | 固定为 `"USD"`。 |
| `balance` | 钱包余额，保留 4 位小数。参见下方注意事项。 |
| `frozen_balance` | 冻结的钱包余额，保留 4 位小数，为参考值。参见下方注意事项。 |
| `observed_at` | 读取时刻的 UTC 时间戳（RFC 3339）。 |

响应携带 `Cache-Control: no-store`，请勿缓存。

## 错误

所有错误响应统一为 `{"code": "...", "message": "..."}` 形状。

| 状态码 | `code` | 含义 |
|--------|--------|------|
| 401 | `INVALID_ACCESS_TOKEN` | 凭据缺失、格式错误、令牌不存在，**或**账户已被停用。这几种情况被刻意统一为同一响应，避免调用方借助响应差异探测账户状态。 |
| 429 | `INVALID_AUTH_RATE_LIMITED` | 该客户端鉴权失败次数过多，触发临时防爆破限制。 |
| 429 | `RATE_LIMITED` | 触发本接口的每用户请求频率限制（见下文）。 |
| 500 | `BALANCE_UNAVAILABLE` | 当前无法读取余额，请稍后重试。 |

两种 429 响应都携带 `Retry-After`（秒）响应头，客户端应至少等待该时长后再重试。

## 频率限制

本接口按**每用户每分钟**限流，限额由管理员配置（默认 60 次/分钟），且与推理接口的 RPM 限制完全独立：

- 调用 `/api/v1/open/balance` 不会消耗推理接口的速率限额或配额；
- 发起推理请求也不会消耗本接口的查询频率限额。

## 重要：这是钱包余额，不是订阅额度

`balance` 与 `frozen_balance` 反映的是账户的**充值钱包**，只有走钱包扣费的用量（例如按量计费）才会影响它。如果账户使用的是**订阅计费**，用量走的是订阅额度而非钱包，因此本接口通常会显示 `0`——这是预期行为，**不代表**账户没有可用额度。订阅剩余额度请到面板查看。

## 重要：`balance` 与 `frozen_balance` 不是同一时刻的原子快照

`balance` 来自一个随计费实时递减的缓存值；`frozen_balance` 则单独从账户记录读取。两者的新鲜度可能不同，在并发用量下可能相差几秒——它们是两个在大致相同时刻分别观测到的相关数值，而不是一次原子快照。请勿基于 `balance` 与 `frozen_balance` 之间应严格满足的关系（例如两者之和）构建业务判断。

## 余额是最终一致的，并非严格单调递减

这是底层余额缓存**本来就有**的行为，并非本接口引入。如果缓存的余额值恰好在账户记录完成回写之前过期，随后的一次读取可能会短暂读到略旧的数据库值，表现为余额看起来短暂"回升"，但实际上并没有到账。请将 `balance` 视为最终一致：它会在短时间内收敛到正确值，但不要假设连续两次读取一定是非递增的。


```json
{
  "object": "sub2api.balance",

  "currency": "USD",
  "balance": 12.3457,
  "frozen_balance": 0.9877,
```
